### ロジック面の確認（実装レビュー）

| 項目 | 内容 |
| --- | --- |
| ポイントの二重付与防止 | ポイントは `visits` / `goshuin` 履歴から毎回**導出**。加算処理を持たない |
| オフライン同期の冪等性 | クライアント生成IDで `setDoc(merge)`。`status` のみ `pending → synced` |
| 既存データ互換 | `visits.status` 未設定＝`synced` 扱い。移行不要 |
| 検索フォールバック | Firestore → IndexedDB → 同梱JSON の順に自動切替 |
| 御利益の付与方針 | 由緒が広く知られる11社のみ初期データ。推測付与なし・件数は実データのみ表示 |
| ルール | v1.2 コレクション（deities/benefits/regions は読み取りのみ、collections/rewards は本人のみ、visits の status 更新のみ許可）を追加 |

## 5. 未検証項目（重要）

以下は **実アカウントの認証情報・実機がこの環境に無いため未実施**です。デプロイ後に確認してください。

| 項目 | 理由 | 確認方法 |
| --- | --- | --- |
| Firestore への実書き込み（visits/goshuin/points/collections） | Firebase プロジェクトの認証情報が無い | Google ログイン → 参拝・御朱印・ポイント表示 |
| Cloudinary への実アップロード | 実プリセット未使用 | 御朱印登録 → `res.cloudinary.com/acati1no/...` |
| 複数端末でのオフライン同期 | 実機2台が必要 | 機内モードで参拝 → 復帰 → 同期センター |
| 実 GPS での 300m 判定 | 実機の位置情報が必要 | 神社周辺で参拝記録 |
| 大量データ（4,200件規模）でのスクロール性能 | 現行同梱データは100社 | `shrines.v2.json` 差し替え後に実測 |
| firestore.rules のデプロイ検証 | `firebase` CLI と実プロジェクトが必要 | `firebase deploy --only firestore:rules` |
| 実機での PWA インストール | ヘッドレス環境では不可 | Android Chrome / iOS Safari |

## 6. テスト上の割り切り

- 位置情報はヘッドレスブラウザで取得できないため、検証用の「テスト位置」機能を使用
- オフライン検証は Playwright の `context.setOffline(true)` によるネットワーク遮断で代替
- Cloudinary の処理テストは `fetch` をスタブして実施（実通信なし）
